# ClimateSense

**Know when it is safe to be outside.** Heat and air-quality risk for eight Indian cities, with
7-day forecasts, daylight-aware safe windows, sport-specific thresholds, a pollution-source
policy brief, and a chat assistant that answers only from the platform's own live data.

- **Live site:** https://kush-710.github.io/ClimateSense/
- **Live API:** https://climatesense-api.onrender.com/docs

Cities covered: Delhi, Bengaluru, Mumbai, Chennai, Kolkata, Hyderabad, Pune, Lucknow.

---

## The problem

"Is it too hot to train today?" is not answerable from a temperature reading. 34 C in dry Delhi
heat and 34 C in humid coastal Chennai are completely different physiological loads, and neither
tells you anything about the air you would be breathing while you exercise.

The metrics that actually matter are harder to get:

- **WBGT** (Wet Bulb Globe Temperature) is what sports-medicine and military work/rest guidance is
  written against, because it combines heat, humidity, wind and solar load. Almost no consumer
  weather source reports it.
- **AQI** is reported on different national scales. The same air gives a very different number on
  India's CPCB scale than on the US EPA scale most international apps show.
- **Thresholds are activity-specific.** A marathon is unsafe at conditions a casual walk is fine in.

ClimateSense computes all three and translates them into a plain answer: what the risk is now, when
today's safe window is, whether your specific sport is cleared, and what is driving the pollution.

---

## What it does

**Current risk** - a 0-100 composite score (WBGT 40%, AQI 30%, temperature 20%, UV 10%) mapped to
SAFE / MODERATE / HIGH / CRITICAL, with an air-quality floor so a cool night under "Poor" air can
never report SAFE.

**Safe window** - the longest run of low-risk daylight hours today. Bounded to 05:00-19:00, because
risk is genuinely lowest at 3am and nobody schedules a PE class then.

**Sport fitness check** - current conditions against published limits for eight activities
(marathon, cricket batting/fielding, football, cycling, school PE, and so on), checked against WBGT
first since that is the standard the thresholds are defined on.

**7-day forecast** - Prophet models per city for temperature and PM2.5, with the El Nino index fed
in as a live regressor. Each forecast is shown with the model's own walk-forward error, so the
numbers are not presented as more precise than they are.

**Policy brief** - ranked likely pollution sources for the city and season, drawn from published
apportionment studies, re-weighted by live meteorology, and mapped to concrete interventions with
the responsible agency. For Delhi it also shows the live GRAP stage.

**Chat assistant** - ask questions in plain language ("is it safe to run in Chennai today?", "how do
we reduce AQI here?", "will El Nino continue?"). Answers are generated by Gemini from a JSON context
built entirely from the platform's own data, and the model is instructed to say so when the data
does not cover the question rather than guess.

## How it works

```
NOAA CPC ONI ---------+
NOAA CPC ENSO probs --+
Open-Meteo forecast --+--> pipeline/fetch.py (async, retries)
Open-Meteo archive ---+              |
Open-Meteo air quality +             |
AQICN ground stations +              v
                            pipeline/transform.py
                            (WBGT, heat index, CPCB AQI,
                             EPA sub-index inversion, gap fills)
                                     |
                                     v
                            pipeline/load.py  -->  Postgres / SQLite
                            (idempotent upserts)
                                     |
            +------------------------+------------------------+
            v                        v                        v
      ml/features.py          services/source_inference.py   services/translation.py
      ml/train.py             (apportionment priors x         (risk -> plain language,
      (Prophet + XGBoost)      live meteo -> ranked sources)   safe windows, sport verdicts)
            |                        |                        |
            +------------------------+------------------------+
                                     v
                          api/main.py  (FastAPI)
                    /climate  /forecast  /policy  /enso
                    /cities   /models    /assistant/ask
                                     v
                          docs/  (static site, GitHub Pages)
```

Data refreshes every 30 minutes through a GitHub Actions cron that runs the live ETL against the
hosted database. CI runs the test suite on every push.

## Data sources

| Source | Provides | Key needed |
|---|---|---|
| Open-Meteo Forecast | Hourly weather incl. shortwave radiation, 7-day horizon | No |
| Open-Meteo Archive | Historical hourly weather back to 2000, for training | No |
| Open-Meteo Air Quality | Hourly PM2.5/PM10/NO2/O3/SO2/CO from the CAMS model | No |
| AQICN (WAQI) | Live ground-station readings, best Indian coverage | Free token |
| NOAA CPC ONI | Current and historical El Nino index (Nino-3.4 SST anomaly) | No |
| NOAA CPC ENSO probabilities | Official forward-looking ENSO probability forecast | No |
| Published apportionment studies | PM2.5 source shares per city and season | No (encoded) |
| CAQM GRAP framework | Official AQI-triggered policy stages I-IV | No (encoded) |

Everything runs on free tiers. Total hosting cost is zero.

## The science, and where the estimates stop

**WBGT** is computed, not approximated by a heat index:

```
WBGT = 0.7 * Tnwb + 0.2 * Tg + 0.1 * Ta
```

Natural wet-bulb uses the Stull (2011) psychrometric fit; the black-globe term uses the
Hunter-Minyard (1999) regression driven by real shortwave radiation. This is an *estimate*: a true
Liljegren solve needs a direct/diffuse radiation split and a measured globe thermometer. It is good
enough to rank hours and flag unsafe sessions, not to certify a worksite.

**AQI** uses India's CPCB breakpoints throughout. AQICN reports EPA *sub-indices* rather than
concentrations, so those are inverted back to ug/m3 before CPCB breakpoints are applied, keeping
every stored AQI on one scale. Because of this, the numbers here will not match the EPA-scale
figures Google or IQAir show for the same air. Both are correct; they are different yardsticks.

**ENSO** appears twice: the current ONI value feeds the forecast models as a regressor, and NOAA
CPC's official probability outlook (a genuinely forward-looking product, unlike the ONI file) drives
the outlook line. The winter PM2.5 narrative is only stated for Indo-Gangetic cities, where that
inversion mechanism actually applies.

**GRAP** is CAQM policy scoped to Delhi-NCR, so a stage is only reported for Delhi. Other cities get
the national CPCB AQI category instead of a framework that does not apply to them.

**Source apportionment** is source-*likelihood inference*, not chemical apportionment, which would
require speciated measurements and a receptor model. Cities without an encoded published study fall
back to a clearly-labelled generic urban prior rather than borrowing another city's citations.

## Model results

Prophet, walk-forward cross-validated (MAE):

| City | Temperature (C) | PM2.5 (ug/m3) |
|---|---|---|
| Delhi | 3.74 | 28.80 |
| Bengaluru | 1.11 | 8.04 |
| Mumbai | 1.64 | 16.27 |
| Chennai | 1.52 | 10.41 |
| Kolkata | 2.44 | 17.60 |
| Hyderabad | 1.89 | 10.10 |
| Pune | 1.51 | 10.71 |
| Lucknow | 3.42 | 21.82 |

PM2.5 models take wind and humidity as extra regressors alongside ONI, since ventilation drives
dispersion more than calendar seasonality does.

### A negative result worth reading

The repo also trains an XGBoost risk-tier classifier. **It does not beat a naive baseline, and is
deliberately not used in serving.**

Originally it predicted the *current* hour's risk tier, which was circular: the tier is a closed
form of columns the model already received as features, so it was re-deriving arithmetic and posting
a meaningless F1 around 0.99. Repointed at a genuine +24h target and measured against "tomorrow
looks like today" on matched walk-forward folds:

| City | Model F1 | Persistence baseline | Lift |
|---|---|---|---|
| Delhi | 0.518 | 0.566 | -0.048 |
| Bengaluru | 0.895 | 0.933 | -0.038 |
| Mumbai | 0.815 | 0.832 | -0.017 |
| Chennai | 0.859 | 0.881 | -0.022 |
| Kolkata | 0.710 | 0.726 | -0.016 |
| Hyderabad | 0.867 | 0.889 | -0.022 |
| Pune | 0.871 | 0.899 | -0.028 |
| Lucknow | 0.688 | 0.719 | -0.031 |

It loses in all eight cities. So `/climate`'s 24h outlook applies the transparent risk formula to
the ingested weather forecast instead, which is both more accurate and easier to explain. The model
is still trained and reported at `GET /models` next to its baseline. Re-framing it as a
bias-correction model on the operational forecast is the honest path to making it earn a place.

## Run it locally

Requires Python 3.11 or 3.12 (3.13 works but ML wheels lag).

```bash
git clone https://github.com/kush-710/ClimateSense
cd ClimateSense
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # then fill in the values described below
```

`.env` keys:

| Key | Needed for | Where to get it |
|---|---|---|
| `AQICN_TOKEN` | Live ground-station AQI | https://aqicn.org/data-platform/token/ |
| `GEMINI_API_KEY` | Chat assistant | https://aistudio.google.com/apikey |
| `DATABASE_URL` | Leave unset for local SQLite | Supabase, for deployment |
| `FRONTEND_URL` | CORS allow-list, comma-separated | e.g. `http://localhost:5500` |

Then:

```bash
# 1. Backfill two years of history for all cities (no keys required)
python pipeline/run_etl.py seed --days 730

# 2. Pull current conditions
python pipeline/run_etl.py live

# 3. Train models (repeat per city id 1-8)
python ml/train.py --city 1 --models prophet xgboost

# 4. Run the API
uvicorn api.main:app --reload --port 8000     # http://localhost:8000/docs

# 5. Run the site in another terminal
python serve_docs.py 5500                     # http://localhost:5500

# 6. Tests
pytest tests/ -v
```

`serve_docs.py` disables caching, which matters because the browser will otherwise hold a stale
`app.js` while you edit it. The frontend detects localhost and talks to port 8000 automatically, so
no config change is needed between local and production.

## Deploy your own

1. **Database** - create a free Supabase project and copy the **Session pooler** URI (the direct
   connection is IPv6-only, which most free hosts cannot reach).
2. **API** - on Render, New -> Blueprint, pick your fork. `render.yaml` defines the service; set
   `DATABASE_URL`, `GEMINI_API_KEY`, `AQICN_TOKEN` and `FRONTEND_URL` in the dashboard.
3. **Seed the cloud database** once: `DATABASE_URL="..." python pipeline/run_etl.py seed --days 730`
4. **Frontend** - set `PROD_API` at the top of `docs/app.js` to your API URL, push, then enable
   GitHub Pages from `main` / `/docs`.
5. **Keep it fresh** - add `DATABASE_URL` and `AQICN_TOKEN` as Actions secrets so the 30-minute ETL
   cron can reach your database.

Trained models are committed, so the API serves real forecasts as soon as it boots. On Render's free
plan the service sleeps after about 15 minutes idle, so the first request after a quiet spell takes
roughly 30-50 seconds to wake.

No secrets live in this repository. Everything is read from environment variables, and `.env` is
gitignored.

```
tests/        pure-logic tests, no network or database required
```

## Known limitations

- WBGT is estimated from published approximations, not measured.
- Open-Meteo's air-quality feed is a model (CAMS), not a sensor, and its most recent hours are often
  incomplete. Where a ground station is available via AQICN it is preferred; otherwise the freshest
  available reading is used and labelled with its own timestamp.
- Model-versus-station PM2.5 can differ substantially. Both values are stored with their source.
- The risk score's weights are a documented judgement call, not a clinically validated instrument.
- Source likelihoods are decision support, not measurement. Verify the encoded share ranges against
  the cited studies before using them in anything published.
